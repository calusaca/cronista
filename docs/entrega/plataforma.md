CATEGORY: Best Multi-Agent Orchestration (Best Multi-Agent System in the official rules), built with another supported orchestration approach: custom TypeScript orchestration, a Microsoft Foundry agent and a read-only MCP server. Distinct roles: two LLM coaches, an LLM commentator, a template narrator, a deterministic statistician, a verifier, a Foundry analyst agent and a crónica writer that retrieves its match facts through the MCP server. Shared state: one match journal in Blob Storage under a lease. Handoffs: committed observation → coach plans → shared engine → broadcast desk. Recovery: an invalid or late plan falls back to a logged programmed plan; a sentence that fails V1–V8 is retried with the failed rule, then replaced by a labelled template. Also fits Best Azure Cloud Native Integration.

PIPELINE
Ingest: the agent-generated event stream (passes, shots, tackles, fouls, offsides, possession changes) is consumed live by every downstream stage. Interpret: a deterministic statistician turns them into stats and key moments. Explain: the commentator says why a moment matters, citing event ids. Render: on-screen desk, live stats, player card and a machine-readable overlay JSON. Personalize: Fan, Analyst and follow-a-player views, favourite club and player, English or Spanish.

SYNTHETIC DATA: GENERATED BY AGENTS, THEN CONSUMED
Generation and consumption are separate stages. First the two LLM coaches play: their plans change from one match to the next, so every model match is a new event stream rather than a scripted replay, and six models give many different pairings and styles. A deterministic engine, calibrated against 85 statistical checks (passes, shots, fouls, offsides, penalties, goals), keeps that data football-realistic. Then the rest of the system consumes only that stream: the pitch animation, the narrator, the commentator, the statistician, the live stats, the Foundry analyst, the downloadable commentary (Markdown and JSON) and the post-match report all read the same confirmed events and frames. The "Match report" button turns any finished match into a written report: GPT-6.1 Sol writes it from that match's facts, which the crónica agent retrieves through CRONISTA's read-only MCP server (Model Context Protocol, the same server any MCP client such as GitHub Copilot can query); every sentence passes V1–V8 and links to its events, and the author is always labelled. Every recording stores the coaches' plans and its rules version, so it replays exactly without calling the models again. A separate seeded 90-minute simulator powers the original recap demo and a documented, byte-reproducible dataset (DATASHEET and JSONL sample).

WHAT WE BUILT
CRONISTA is a multi-agent football broadcast on Azure that turns synthetic match events into explainable, personalized match intelligence. Two LLM coaches, drawn from six Azure OpenAI deployments, receive the same observation and return strict JSON plans; a shared deterministic engine resolves passes, shots, tackles, fouls, offsides and goals. A three-voice desk narrates live in English or Spanish through Azure Speech: a template narrator calls the play, an LLM commentator may only analyse with cited facts, and a deterministic statistician quotes the numbers. A Microsoft Foundry agent answers viewer questions with read-only tools.

WHY IT MATTERS
AI commentary is fluent but hard to trust. In CRONISTA every sentence passes deterministic verifier rules (V1–V8) and links to its events; a failed sentence is retried with feedback, then replaced by a labelled template. "Inspect facts and checks" shows the proof on screen.

PERSONALIZED
Fan, Analyst and follow-a-player views; favourite club and player with "Only my player"; live stats and a player card with distance and top speed; ES/EN text and voices; a six-model tournament; replays and downloadable recordings; a reproducible synthetic dataset and overlay JSON.

MICROSOFT AND AZURE
